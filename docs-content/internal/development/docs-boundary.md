# 文档分层规范（内部站 vs 公开站）

## 目标

把文档按受众拆分为两套：

- **内部站（internal-docs）**：运维、凭证、架构细节、调试流程、故障日志。
- **公开站（docs）**：产品介绍、公开能力、案例、对外 FAQ。

---

## 内部站允许内容

- 基础设施拓扑、内网地址、端口映射。
- 运维手册、故障处理、值班与应急流程。
- 仅团队可见的架构细节与实验记录。

## 公开站允许内容

- 产品价值、功能边界、使用方式、公开路线图。
- 对外演示链接、公开 API 说明（脱敏后）。
- 不包含任何账号、密码、Key、内网地址、服务器 IP。

---

## 严禁出现在公开站的内容

- 用户名/密码、Token、API Key、SSH Key 文件名。
- 数据库连接串、容器仓库密码、第三方平台管理入口。
- 内网网段、生产服务器 SSH 登录信息、故障排查细节日志。

---

## 维护流程

1. 任何文档新增前先判断受众：`internal` 或 `public`。
2. 公开文档发布前做一次脱敏审查（链接、截图、代码块）。
3. 项目技术细节以代码仓库 README 为准，公开站只保留可对外的信息。
4. 内部站和公开站禁止互相直接复制整页，避免信息漂移。
