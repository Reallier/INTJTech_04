## AI Agent 开发反思

### 从"全能员工"到"自动化脚本"

- 现阶段大模型技术**远未达到能支撑拟人化管理职能的高度**
- 所谓的 Agent 本质上依然只是"智能脚本"
- 过度设计导致**管理成本远超产出**的死循环

### "小作文协作"的陷阱

> 让低级模型给高级模型写"工作汇报"，自然语言的传递引入噪声和幻觉，导致错误被层层放大。

**解法**：强制输出**结构化 JSON 数据**，低级模型是"数据清洗器"而非"汇报者"。

### LLM 的正确定位

> **"LLM 是处理非结构化数据的'翻译插件'，不是流水线的主宰。"**

## ToB vs ToC 产品定位

| 维度 | **ToC / 内部效率型** | **ToB 商业包装型** |
|------|----------------------|-------------------|
| **核心价值** | 省时间、路径最短 | "数字员工"叙事、品牌溢价 |
| **技术架构** | OIS：JSON-First、确定性 | 可以更重：LangGraph、拟人化 |
| **用户界面** | 越少交互越好 | 需要"仪式感" |
| **开发心态** | 功能驱动 | 演示驱动 |

## 产品线架构策略

### 当前问题："官网 + 产品列表"

```
INTJTech Official Site
    ├── TalentAI (app01)
    ├── Closer (app02)
    └── ...（10+ 产品）
```

**问题**：品牌稀释、SEO 分散、用户心智负担

### 推荐方案

| 产品类型 | 策略 |
|---------|------|
| **核心商业产品** (TalentAI, Closer) | 独立域名/子域名 + 独立 Landing Page |
| **效率工具** (简历修改, Boss求职) | 挂在官网"工具"板块 |
| **内部/实验性产品** | 不对外或放"Labs"板块 |

### 替代方案

1. **拆分独立品牌**：`TalentAI.cn`、`Closer.intjtech.cn`
2. **产品矩阵分层**：核心产品 / 效率工具 / 实验室
3. **Mother + Sub-Brands**："TalentAI 是简序智能旗下产品"

## 核心原则

1. **"用"和"卖"分开**：内部追求确定性 (OIS)，ToB 追求情绪价值
2. **同一引擎，两套皮肤**：核心 OIS + 对外包装壳子
3. **品牌聚焦**：核心产品值得独立身份
4. **可观测性 > 智能**：可追踪比"聪明"更重要

## 2026-02-23 国际版重构：从"SaaS超市"到"Boutique Lab"

### 诊断问题
之前的官网（特别是国际版）存在严重的**认知分裂**：
1. **硬核 B2B 与玩具 B2C 混杂**：高价值的红队测试/私有化部署服务，与 MBTI (MindAI)、Meme 表情包识别 (Photo Intelligence) 放在同一个层级。这会导致严肃的企业客户怀疑团队的工程定力。
2. **产品与服务倒挂**：TalentAI 作为拳头产品放在最前，但实际上目前最能带来现金流的高利润业务（私有化 AI 基建部署、RAGFlow / Garak 实施）被压在页面底部，被当成普通外包服务。
3. **理念输出过于学究化**：将复杂的工程哲学（如“双重客体化秩序”）直接铺载在公司主页，增加了 B2B 客户的认知负担。他们关心的是“数据安全”与“不出现幻觉”，而不是深刻的系统交互理论。

### 战略调整（Boutique Lab 定位）
全站叙事从“一家有很多产品的 SaaS 公司 (We)” 变为 **“由顶尖工程师主导的数字实验室 (Personal Lab - I/My crew)”**。这是为了建立“一种克制的傲慢和极客的真诚”。

1. **核心资产 (The Serious Stuff)** 
   - TalentAI 定义为 **Venture（商业化产品）**，强调“为了解决我自己的效率瓶颈而建，现在服务于企业”。
   - 技术服务拔高为 **Boutique Engineering & Ops（精品特种运维）**，只对接 CTO 和工程团队，专注高端私有化 AI 基建。
2. **实验室与后花园 (The Playground)**
   - MindAI、Photo Analysis 被明确降级/归类为 **Experiments（实验性项目）**。
   - 这不仅剥离了它们对 B2B 品牌专业度的稀释，反而把它们变成了展现底层筋肉（逻辑推理、多模态处理）的 Tech Showcase。
3. **内容引流机制**
   - 保持主页的极度克制，将晦涩但极其深度的长文（Agent 第一性原理、Schema-First 协议等）全部转移至 **Engineering Blog**，作为沉淀死忠极客粉丝的私域引力引擎。
