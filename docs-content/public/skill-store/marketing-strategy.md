## 三、内容策略：测评引流

### 3.1 核心逻辑

> **测评即内容，权威即流量**

通过客观、专业的技术测评，在公域平台建立"懂行"的品牌认知，引流至官网。

### 3.2 测评选题矩阵

| 优先级 | 选题 | 热度 | 专业壁垒 | 与产品关联 |
|:---|:---|:---|:---|:---|
| 🔥 P0 | MCP Server 横评（filesystem/github/postgres...） | ⭐⭐⭐⭐ | ⭐⭐⭐ | 高 |
| 🔥 P0 | AI 编程助手评测（Cursor vs Copilot vs Claude Code） | ⭐⭐⭐⭐⭐ | ⭐⭐ | 中 |
| P1 | AI Agent Skills 生态盘点 | ⭐⭐⭐ | ⭐⭐⭐⭐ | 高 |
| P1 | 简历解析 API 对比（关联 TalentAI） | ⭐⭐ | ⭐⭐⭐⭐⭐ | 极高 |
| P2 | MCP 协议深度解读 | ⭐⭐ | ⭐⭐⭐⭐⭐ | 中 |

### 3.3 建议首发选题

**《2026 主流 MCP Server 实测横评：哪些值得接入？》**

理由：
- 紧贴当前页面定位（技术选型中心）
- 测评结果可直接复用到官网"精选开源"板块
- 自然植入 INTJsys 自研 MCP（intjsys-talentai）

### 3.4 测评维度模板

| 维度 | 权重 | 说明 |
|:---|:---|:---|
| 功能完整度 | 30% | 支持的操作数量 |
| 响应延迟 | 25% | P99 延迟 |
| 稳定性 | 25% | 24h 连续运行错误率 |
| 文档质量 | 10% | README/示例完整度 |
| 社区活跃 | 10% | GitHub Stars / Issue 响应 |

## 四、公域平台布局

### 4.1 平台策略

| 平台 | 内容形式 | 目标 | 优先级 |
|:---|:---|:---|:---|
| **知乎** | 长文回答 + 专栏文章 | SEO + 专业形象 | P0 |
| **掘金** | 技术文章 | 开发者社区渗透 | P0 |
| **微信公众号** | 精简版 + 落地页引导 | 私域沉淀 | P1 |
| **GitHub** | 测评数据/脚本开源 | 技术可信度 | P0 |
| **即刻/X** | 短图文 + 结论速览 | 快速传播 | P2 |

### 4.2 分发策略

1. **知乎/掘金**：发完整版（5000-8000 字）
2. **公众号**：发精简版（2000 字 + "阅读原文"跳官网）
3. **GitHub**：放测评脚本 + 原始数据（建立技术公信力）
4. **短平台**：发结论图表（快速传播）

## 六、执行节奏

### 6.1 单篇测评周期（约 2-3 周）

| 阶段 | 时间 | 交付物 |
|:---|:---|:---|
| 调研 | 3-5 天 | 确定测评对象 + 维度 + 脚本 |
| 测评 | 5-7 天 | 跑数据 + 整理结论 |
| 写作 | 3-5 天 | 完成长文 + 适配各平台版本 |
| 发布 | 1 天 | 多平台同步发布 |
| 二次传播 | 持续 | 结论图表 + 社群讨论 |
